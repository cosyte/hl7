`parseHL7` now builds each segment's tree the first time something reads it, instead of every segment during the parse; pass `{ lazy: false }` to build the whole tree during the parse as before. The parse still reads the whole message once and reports every warning before it returns, so `warnings`, `strict` and `onWarning` behave exactly as they did, and nothing is reported later on first read. What moves from the parse to the first read is the building of each segment's fields, repetitions, components and subcomponents: `get(path)` builds the segment its path reaches, a `Segment` from `segments()`, `part()` or `allSegments()` builds when its fields are first read, and an edit builds the segment it changes. `rawSegments`, `toString()`, `toJSON()`, `prettyPrint()` and the helpers that read every segment of a type (such as `observations()`) build every segment they reach. A lazy message keeps the message text until it is released. Every value, warning, error and `toString()` output is the same in both modes. A 1 MiB result report read at MSH, PID, PV1 and five OBX now holds about 2.5 times its size instead of about 45 times, and `{ lazy: false }` builds the whole tree faster than the parse did before. `Hl7Message.rawSegments`, `Segment.fields` and `Segment.raw` stay own enumerable properties with the same types, so a message or segment logs, serializes and spreads exactly as before, read or not, and never shows text from another segment. The frozen `fields[0]` placeholder of a standard segment name (and of MSH-1) is now one node shared by every message, as the empty and null field nodes already were.
