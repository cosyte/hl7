Immunizations now say whether a record is a dose given: every entry `msg.immunizations()` returns carries `administrationStatus`, derived from that RXA's own RXA-21, RXA-5 and RXA-20. A refusal, a not-administered record, a CVX `998` "no vaccine administered" placeholder and a request to delete an administration sent earlier no longer share one list with doses given and no field telling them apart.

- `administrationStatus.classification` is one of `completed`, `not-done`, `no-vaccine-administered`, `delete-requested` or `undetermined`.
- One rule decides, the first that applies: RXA-21 exactly `D` is `delete-requested`; an RXA-21 present but not exactly one of `A`, `D`, `U`, `X` (HL7 Table 0323) is `undetermined`; RXA-5 carrying CVX `998` is `no-vaccine-administered` whatever RXA-20 says, or `undetermined` when the other RXA-5 triplet carries a different identifier; otherwise RXA-20 by HL7's Table 0322 to Event Status map, `CP` and `PA` `completed`, `RE` and `NA` `not-done`. RXA-21 `A`, `U`, `X` and empty change nothing.
- `undetermined` is the fail-safe. An empty, absent or `""` RXA-20 and any RXA-20 or RXA-21 that is not exactly one code (a lowercase `cp` or `d`, whitespace around it, a VT or FS byte inside it, a code written as an escape sequence, or more than one repetition, component or subcomponent such as `D~A`) is `undetermined`. Only an exact `CP` or `PA`, with RXA-21 empty or exactly `A`, `U` or `X` and no CVX `998`, is ever `completed`.
- `administrationStatus.completionStatus` and `administrationStatus.actionCode` are the raw RXA-20 and RXA-21 codes, byte-identical to the entry's `completionStatus` and `actionCode` and absent exactly when those are. `administrationStatus.decidedBy` names the field that decided and what it read: HL7 Table 0322 version `3.0.0` with the map's canonical URL and version `1.0.0`, HL7 Table 0323 version `3.0.0`, or the CDC CVX code set for `998`.
- A status is reported, never applied: a `delete-requested` record is still returned in document order, and nothing is removed, merged or matched against an earlier message. Each RXA classifies from its own fields; nothing is carried across segments. `completionStatus`, `actionCode` and every other existing key are unchanged.
- New exported types: `ImmunizationAdministrationStatus`, `ImmunizationStatusClass`, `ImmunizationStatusBasis`, `ImmunizationStatusTable`, `ImmunizationStatusMap` and `ImmunizationStatusCodeSet`. `Immunization` gains the required `administrationStatus` key, so code that builds `Immunization` objects by hand must now supply it.
- New docs page: `docs-content/spec-notes-immunization-status.md`.
