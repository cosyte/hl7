# @cosyte/hl7 0.1.0 release readiness

- package: `@cosyte/hl7`
- from: `0.0.10`
- target: `0.1.0`

This file is the evidence a maintainer says yes or no to `0.1.0` on. It is validated by
`scripts/release-readiness.ts`, which reads it beside `.changeset/` and `package.json` and refuses
if the two ever describe different releases. It is not in `package.json#files`, so no consumer
receives it.

## The decision this records

`@cosyte/hl7` has been publishing on the `0.0.x`-until-first-alpha ladder, and every pending
changeset in this queue was filed asking for `patch`, because the repository's own contributor
guidance told every contributor to pick `patch` while that ladder held. A queue classified that way
resolves to `0.0.11` no matter what is in it.

What is in it is not a `0.0.11`. Twelve of the eighteen pending declarations add behaviour a
consumer can call that did not exist before: five new typed message builders, conformance condition
predicates, coding-system bindings on a value set, a declared profile conformance level, component
rules on a field rule, declared conditional usage with caller-supplied resolutions, a
message-structure registry derived from HL7's published structures instead of hand-transcribed,
typed message overlays that narrow a message to its type, custom-segment field names checked
against the profile that declared them, an opt-in validator that checks a message against the
published structure for its trigger event, schema emission for the serialized projection, and
profile-declared field names on standard segments. The aggregate of those twelve `minor`
declarations against `0.0.10` is `0.1.0`, so leaving the ladder is what the queue already says, once
each file says what it actually does.

Nothing in this file bumps a version or publishes anything. The bump is `changeset version`'s, in
the Version PR the release pipeline opens; the publish is `changeset publish`'s after that.

**Publication of `0.1.0` awaits the release frequency policy (S0161); this record certifies that the
queue is ready, not that the release may go out today.**

## Break candidates

A break candidate here is a public export or a stable warning code that a pending changeset
**removes, renames or narrows**. Eight were found; they are listed rather than absorbed, and none
of them is being released as a `major`. On a `0.x` line semver carries a breaking change in the
minor position, and `major` would resolve to `1.0.0`, which is a claim that this API is stable at
1.0 and is not the claim this release makes.

No pending changeset removes or renames a warning code or a finding code. `WARNING_CODES` stays at
twenty entries; `FINDING_CODES` gains three and renames none. `olive-swans-arrange.md` adds a
separate registry, `STRUCTURE_FINDING_CODES`, rather than extending `FINDING_CODES`, so no consumer
switching over the conformance codes gains an arm.

1. **`buildAdt` narrows.** `great-otters-author.md`. For the ten trigger events whose published
   structure requires `MRG` (A40, A41, A42, A43, A44, A45, A47, A49, A50, A51), a call with no
   `priorIdentity` used to return a message carrying a `MISSING_EXPECTED_GROUP` warning and now
   throws a `TypeError`. Remedy: supply `priorIdentity`, or use `buildMessage` where an incomplete
   message is what is wanted.
2. **`USAGE_CODES` is retyped and `UsageCode` widens.** `tall-comets-declare.md`. `USAGE_CODES` is
   now `readonly UsageCodeRegistryEntry[]`, which is not assignable where a rule usage is expected,
   and `UsageCode` now admits the declared-conditional template `C(t/f)`, so an exhaustive `switch`
   over it no longer compiles without new arms.
3. **`Meta.timestamp` narrows for order-ambiguous slash dates.** `olive-badgers-refuse.md`. A
   slash-separated numeric date whose first two components are both in 1-12 no longer resolves;
   `msg.meta.timestamp` comes back `valid: false` with an `AMBIGUOUS_DATE_ORDER` report. Remedy:
   declare the order, `parseHL7(raw, { dateFormats: ["MM/DD/YYYY"] })`.
4. **`MessageStructure.missingGroups` changes what it holds.** `olive-lions-derive.md`. It used to
   hold hand-picked group labels and now holds segment names. The field, its type and its meaning
   are unchanged; code matching its values is not.
5. **`Segment.type` changes what it reports.** `olive-pandas-repeat.md`. It used to carry the wire
   spelling verbatim and now reports the canonical uppercase spelling. Remedy: read
   `Segment.raw.name` for the spelling the sender sent.
6. **Profile definition narrows on usage and cardinality.** `quiet-pandas-declare.md`. A rule
   pairing `C`, `CE`, `O`, `X`, `B` or a declared conditional with a minimum cardinality above 0,
   or `R` with a minimum of 0, or `X` with a maximum other than 0, defined cleanly before and is
   now `PROFILE_MALFORMED` from `validateAgainstProfile` and a thrown `ProfileDefinitionError` from
   `defineConformanceProfile`.
7. **Strict mode narrows for a lowercase custom-segment claim.** `olive-pandas-repeat.md`. A
   hand-rolled profile keyed with a lowercase `customSegments` name, parsed strict against a
   matching lowercase segment, gains a `SEGMENT_CASE` warning, which strict mode promotes to a
   throw.
8. **`Segment.get` narrows its argument.** `olive-otters-declare.md`. On a segment obtained BY TYPE
   from a message parsed with a statically known profile, `get` accepts only the names that profile
   declares for that segment type; passing any other literal stops compiling. Nothing narrows at run
   time, and the only calls affected are ones already reading `undefined`, since an undeclared name
   never resolved to a field. Remedy: correct the name, read the segment off `msg.allSegments()`
   (which still takes any `string`), or annotate the profile `Profile` to give the narrowing up.
   This repository's own suite carried exactly one such call, and it is now a `@ts-expect-error`
   asserting both halves.

Three further changes are additive at runtime but break an exhaustive `switch` at compile time, so
they are named here even though they remove, rename and narrow nothing: `IdentityEventKind` gains
`"change"` (`great-otters-author.md`), `FindingCode` gains `PROFILE_CONDITION_UNEVALUATABLE`,
`PROFILE_CODING_SYSTEM_MISMATCH` and `PROFILE_UNDECLARED_CONTENT` (`lucky-hounds-decide.md`,
`olive-comets-bind.md`, `quiet-pandas-declare.md`), and `UsageCode` gains `B` alongside the
template form already listed above.

## Public export surface

`release/public-api.json` is the written-down public type surface, derived from a fresh build's
`dist/index.d.ts`. `test/scripts/api-surface.test.ts` rebuilds and re-derives it on every
`pnpm test` and fails naming every export that was added, removed or changed. It is the baseline a
later release is compared against; it is not itself a claim that the surface is finished.

## Re-deriving all of this

```bash
pnpm tsx scripts/release-readiness.ts   # this file against .changeset/ and package.json
pnpm build && pnpm tsx scripts/api-surface.ts   # the inventory against a fresh build
pnpm test                                # both of the above, plus the real changeset version run
```
